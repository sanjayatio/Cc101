   Read this document first; follow cross-references for deeper detail.

1.  Report patterns


1.1.  Weekly Gunsmoke

   Summarize the weekly results of an `owner`. Within a day an `owner`
   might perform the `task` multiple times or not at all.

   The report image contains one or more date sections. Each date section
   is preceded by a dark separator band carrying the date label (MM/DD).
   Within a date section, rows are separated by thin dark bands (~9px).

   Row layout:

      +--------------------------------------------------------------------------------------------------+
      | Date (month/day) - dark separator band, not always present                                       |
      +----------+--------------+--------+--------+--------+--------+--------+--------+----------+-------+
      | `owner`  | `owner` name | `buff` | `doll` | `doll` | `doll` | `doll` | `doll` | (ignore) | score |
      | frame    |              | frame  | frame  | frame  | frame  | frame  | frame  |          |       |
      | (ignore) | (OCR)        | (OCR)  | (map)  | (map)  | (map)  | (map)  | (map)  |          | (OCR) |
      +----------+--------------+--------+--------+--------+--------+--------+--------+----------+-------+

   Expected output: comma-delimited CSV per row with columns:
      date, ownerName, buffName, doll1, doll2, doll3, doll4, doll5, score

   Output file: defaults to <image_name>.csv in the same folder as the
   input image, EXCEPT when the image resolves under tests/inputs/ (a
   committed test fixture) -- there the default redirects to
   tests/outputs/weekly_gunsmoke/<image_name>.csv instead, mirroring the
   tests/outputs/daily/ convention used by Daily Gunsmoke.  This avoids
   generated CSVs being left behind next to committed fixture PNGs.
   --output always overrides this default.

   Asset naming convention: prefix asset filenames with '_' to mark them
   as known-mapped (e.g. '_QiongJiu.png'). The leading '_' is stripped in
   CSV output.

   CLI: python main.py <image> [--score-pipeline blob|tesseract]
        Default score pipeline: blob (Tesseract-free, see section 2.4).


2.  Translating image sections

   Not all sections need translating; some must be ignored.


2.1.  Translating `owner name`

   OCR'd directly from the text in the owner name area (top 60px of row).
   Non-alphanumeric characters are stripped. The owner frame (avatar) is
   ignored.

   KNOWN ISSUE: Occasional 1-2 leading noise characters from a rank icon
   at the left edge. See docs/known_issues.txt §2.


2.2.  Translating `buff` frame

   Recognized via OCR of the text label within the buff icon area
   (buff_ocr.py). Does NOT use asset reference images for matching —
   buff icons have dark monochromatic art whose color is not distinctive.
   See docs/decisions.txt §9 for rationale.

   When a new buff is encountered:
      - The buff crop is auto-saved to assets/buff/_<name>.png using the
        OCR'd name.
      - No manual rename is required for new buffs.
      - Invalid names (short words, noise) are rejected by _is_valid_name().

   See docs/decisions.txt §9, §12, §13.


2.3.  Translating `doll` frame

   Mapped via asset lookup (assets/dolls/). Matching pipeline:
      Pass 1  pHash distance <= 6  → match (same session, near-identical)
      Pass 2  HSV histogram >= 0.88 → match (cross-screenshot)
      Pass 3  Unknown              → save GUID for manual labelling

   The histogram uses a mask that excludes optional overlay icons and the
   Lv. badge, keeping only the element icon and face region.
   See docs/decisions.txt §4, §5, §6.

   If no mapping exists:
      - Crop saved to assets/dolls/ as a GUID PNG.
      - User renames the GUID to '_DollName.png'.
      - On next run the renamed file is used.

   When a match is found and the current frame has fewer overlay icons
   than the stored reference, the reference is silently upgraded.


2.4.  Translating score

   Two pipeline options (select with --score-pipeline):

   blob (DEFAULT, Tesseract-free, ~4ms/row):
      Isolates digit blobs via inverse binary threshold, normalises each
      to 20x30px, matches against a per-digit template library using
      1D vertical projection correlation (primary) and Hu moment distance
      (secondary). Templates are stored in assets/fonts/score_digits.py.
      Benchmark: 100% accuracy on the 10-crop ambiguity-ranked test set.
      Run score_detect.py --build to regenerate templates.

   tesseract (fallback, ~200ms/row):
      image_to_string PSM 6; takes the last digit group to discard the
      coin-icon bleed. Falls back to image_to_data with digit whitelist.
      KNOWN ISSUE on Windows: Tesseract state degrades after buff_ocr
      writes a new asset, causing blank scores for subsequent rows.
      See docs/known_issues.txt §1.


3.  Doll frame overlay icons

   A doll frame may carry up to four overlay icons. These MUST be accounted
   for during matching to avoid false negatives.

   3.1  Element icon (top-left, always present)
        The doll's elemental type. SHOULD be used for matching as it helps
        distinguish dolls of the same appearance but different element.

   3.2  Seasonal buff arrow (top-left stack, optional)
        Orange/red upward arrow. Indicates the doll benefits from a seasonal
        buff. MUST be ignored during matching.

   3.3  Selected buff arrow (top-left stack, optional)
        Blue upward arrow. Indicates the doll benefits from the selected
        buff. MUST be ignored during matching.

   3.4  Borrowed indicator (top-right, optional)
        Yellow people icon. Indicates the doll is borrowed from another
        player. MUST be ignored during matching.


4.  Finding data boundaries

   The report image has been screen-captured, meaning:

      - It can have different resolutions across captures
      - Row height may vary by 1-2px between screenshots
      - Column positions are proportional to image width

   Column layout uses binarization-based anchor detection per row
   (layout.py:_detect_columns). The background colour is identified as
   the most-common pixel value; non-background blobs are found via vertical
   projection. The first 5 consecutive same-gap blobs are the dolls; the
   block immediately to their left is the buff.

   Fixed-ratio fallback (used if binarization detection fails):
   Calibrated to a 1485px-wide reference image.

      owner avatar : (0.000, 0.073)  [ignored]
      owner name   : (0.073, 0.323)  [OCR, top 60px only]
      buff         : (0.350, 0.421)
      doll 1       : (0.496, 0.556)
      doll 2       : (0.565, 0.625)
      doll 3       : (0.635, 0.694)
      doll 4       : (0.704, 0.764)
      doll 5       : (0.774, 0.834)
      score        : (0.889, 1.000)  [OCR]

   Row detection uses horizontal brightness projection. Dark bands
   (mean brightness < 70) are separators:
      - Height >= 30px: date separator (OCR'd for date label)
      - Height < 15px: row separator (ignored)

   See docs/technical_design.txt §2.1 for full details.
   See docs/decisions.txt §1, §2 for rationale.


5.  Workflow

   The project has three operation phases.  Phase 1 must be completed before
   Phases 2–3 when starting from scratch; otherwise phases are independent.


5.1.  Production runs

   Weekly Gunsmoke — single image or folder (blob score pipeline, recommended):
      python compile_gfl2.py          # once after any source change
      python main.py <image.png>      # single image → <image>.csv
      python main.py <folder/>        # batch: one <image>.csv per PNG in folder

   Daily Gunsmoke — single image or folder:
      python main.py <image.png> --pattern daily_gunsmoke
      python main.py <folder/>  --pattern daily_gunsmoke

      Side effect: each daily run appends Tesseract fallback events to
      tests/outputs/daily/stat_tess_fallbacks.json (written by flush_tess_fallbacks() in
      daily_gunsmoke.py).  This file is the input to Phase 2 — it records
      which images and stat cells the blob pipeline could not read on its own.

      When Tesseract is used as a fallback (score or stat cell), crop PNGs
      are saved to tests/outputs/daily/ by default for diagnosis.  Disable:
         python main.py <folder/> --pattern daily_gunsmoke --no-save-tess-crops

      Side effect: each daily run (single image or folder batch) also
      writes a structured run report to tests/outputs/daily/reports/
      report_<commit>_<dirty-lines>.py -- a generated Python module (same
      convention as tests/inputs/daily/stat_data.py, not JSON; see
      gfl2/report.py), unconditional, no opt-out flag.  Contains a META
      header (run-start time, wall-clock elapsed, images processed,
      commit/dirty tag, stat-ocr engine) and a SECTIONS dict broken down
      by score / header (dealt/taken/turns) / pct / val, each with a
      processed/ok/failed/unknown_glyphs summary and a pipeline timing
      breakdown (stage, total time, hit count, avg time per hit).  Same
      commit+dirty-lines filename convention as
      debugs/persist_run_result.py -- a report from a dirty tree carries
      dirty_lines > 0 in META and a WARNING in its own docstring, since
      this should generally be run against a clean commit.

   Optional output path (Daily GS only):
      python main.py <image.png> --pattern daily_gunsmoke \
          --output path/to/daily_gunsmoke.js

   With Tesseract score pipeline (not recommended on Windows — see known_issues.txt §1):
      python main.py <image.png> --score-pipeline tesseract


5.2.  Phase 1 — Build templates and capture doll assets
      (one-time, or when adding new images / correcting misreads)

   All Daily Gunsmoke assets in one pass (recommended):
      python assets/builders/build.py "single/*.png"
      python assets/builders/build.py <image.png>           # single image
      python assets/builders/build.py "single/*.png" -v     # verbose
      Extracts doll portraits (-> assets/dolls/),
      header-stat digit templates (-> assets/fonts/stat_header.py),
      and stat-cell pct/val templates (-> assets/fonts/stat_pct.py + stat_val.py).
      Works with single-panel and two-panel images.

   Weekly score templates (blob score OCR classifier):
      python debugs/score_detect.py --build
      Input:  tests/inputs/weekly_scores/manifest.json + crop PNGs
      Output: assets/fonts/score_digits.py

   Doll name projection templates:
      python -m gfl2.doll_name_ocr --build <folder/>
      python -m gfl2.doll_name_ocr --build <img1.png> [<img2.png> ...]
      Templates self-update automatically on each main.py daily run.
      Use --build only for a cold start or after correcting portrait names.

   Doll portraits — automatic, with manual rename step:
      Unknown frames are saved as GUID PNGs to assets/dolls/ during each
      main.py run.  Rename each GUID to _DollName.png and re-run.
      To re-crop at a different resolution:
         python assets/builders/rebuild_assets.py <image.png>


5.3.  Phase 2 — Generate test input sets
      (one-time, or after adding new images / rebuilding templates)

   PREREQUISITE: tests/outputs/daily/stat_tess_fallbacks.json must be populated first.
   This file is written by daily_gunsmoke.parse() → flush_tess_fallbacks()
   during normal production runs (§5.1).  Each main.py daily run appends
   every Tesseract fallback event it encountered to this file.  Without it,
   generate_stat_inputs.py falls back to all single/*.png with no ranking.

   Daily stat-OCR test inputs (tests/inputs/daily/):
      # 1. Run production on your images first (populates tests/outputs/daily/stat_tess_fallbacks.json):
      python main.py <folder/> --pattern daily_gunsmoke

      # 2. Then generate ranked test inputs from those results:
      python tests/generate_stat_inputs.py              # top 20 failing images
      python tests/generate_stat_inputs.py -n 30        # top 30
      python tests/generate_stat_inputs.py single/gm_d_20250929.png

      Reads tests/outputs/daily/stat_tess_fallbacks.json to rank images by Tesseract-fallback count,
      runs the full pipeline (blob -> Tesseract fallback) on the top-N worst,
      and writes tests/inputs/daily/stat_data.py (a generated Python module,
      not JSON) containing:
        CROPS -- ground truth (pct, val) grouped by source image, one entry
                 per part.
        META  -- per-image metadata: doll frames present, which are rare
                 within the set, hard-to-classify ('?') cell count, K/M
                 suffix cells, known structural outliers, and a rough
                 importance_score combining these.
      Crops themselves are not persisted as PNGs; the test suite re-extracts
      them at run time via the shared `daily_stat_crops` fixture
      (tests/conftest.py — pure panel/frame/column segmentation, no OCR
      engine or Tesseract call of any kind).
      Re-run after adding new images or after a Phase 1 build changes accuracy.

      --tess-only (decisions.txt #95): ground truth = pure Tesseract label
      (auto-consulting tests/inputs/daily/tess_gt_cache.py if present, same
      as every engine's own --verify) instead of the production full
      pipeline.  REQUIRED when the resulting stat_data.py will be compared
      against a non-v0_1_0 engine (tests/test_stat_ocr_v0_3_0.py,
      tests/test_stat_ocr_v0_1_1.py — the only two engines this project's
      automated stat-cell hard-case suite currently covers, decisions.txt
      #95) — otherwise the "ground truth" is really just v0_1_0's own
      blob answer, which biases the comparison toward whichever engine
      generated it (the same flaw known_issues.txt §15/§17 already
      document for the old convention).  --no-gt-cache forces live
      Tesseract instead.  Regenerate the committed 18-image fixture set
      with:
         python tests/generate_stat_inputs.py "tests/inputs/daily/*.png" --tess-only

      stat_gt_overrides.json corrections are now APPLIED UNCONDITIONALLY
      after collection, regardless of --tess-only (decisions.txt #95,
      closing action_items.txt #6's clobber-protection bullet) — a bare
      re-run of this script no longer silently discards hand-verified
      corrections.

      CAUTION (still applies without --tess-only): the default (production
      full-pipeline) ground truth cannot catch a case where blob
      confidently returns a wrong answer — that wrong answer becomes
      "ground truth" (docs/known_issues.txt §15).  Re-running this script
      OVERWRITES tests/inputs/daily/stat_data.py from scratch each time.

   Weekly score test inputs (tests/inputs/weekly_scores/):
      Crop PNGs are committed manually from weekly GS runs.
      manifest.json lists {key, path, expected} for each crop.
      After committing new crops, rebuild templates:
         python debugs/score_detect.py --build


5.4.  Phase 3 — Run tests
      (each session, or after any source or template change)

   Compile and run all tests:
      python compile_gfl2.py
      python -m pytest tests/ -q --no-header --tb=short

   Run a single test file:
      python -m pytest tests/test_stat_ocr_v0_3_0.py -q --no-header --tb=short

   --- tests/test_weekly_gunsmoke.py ---
      End-to-end parse of gm_250801.png and gm_250730.png.
      Asserts correct date, ownerName, buffName, doll1-5, score per row.
      A failure indicates a regression in layout detection, OCR, or asset
      matching.

   --- tests/test_stat_ocr_v0_3_0.py / tests/test_stat_ocr_v0_1_1.py ---
      (decisions.txt #95) The daily stat-cell hard-case suite covers
      EXACTLY TWO engines — gfl2.stat_ocr_v0_3_0.StatOcrV0_3_0 and
      gfl2.stat_ocr_v0_1_1.StatOcrV0_1_1 — deliberately, not v0_1_0
      (gfl2.stat_ocr_v0_1_0.StatOcrV0_1_0) or the exploratory gfl2.stat_ocr_v0_2_0.py: this
      keeps both engines under active comparison so the codebase stays
      honest about which pipeline code is generic (segmentation/crop
      extraction — shared via the `daily_stat_crops` fixture,
      tests/conftest.py) versus engine-specific (each engine's own
      classify()/read()).  Both files target tests/inputs/daily/*.png (the
      committed, curated 18-image fixture, §5.3) and the SAME ground truth
      (tests/inputs/daily/stat_data.py, regenerated with --tess-only so it
      isn't biased toward either engine's own answer) so the two engines'
      results are directly comparable.  Crop extraction never calls an OCR
      engine or Tesseract — a failure here is always the engine's own
      classify() logic, nothing else can quietly resolve it underneath.

      test_stat_ocr_v0_3_0.py: v0_3_0 is expected to pass cleanly.  Known cases
      are xfail(strict=True) (docs/known_issues.txt §36) so a fix shows up
      as an unexpected pass, forcing the xfail's removal.

      test_stat_ocr_v0_1_1.py: v0_1_1 has real, standing, unresolved gaps
      (docs/known_issues.txt §14/§18/§36).  Known-failing cells are
      EXCLUDED from the parametrization entirely (pytest.mark.skip, listed
      in `_EXCLUDED` with a reason) rather than xfail — the point isn't
      "this assertion is expected to fail" but "this is an accepted gap,
      not worth asserting against every run."

      Corrections to stat_data.py's ground truth live in
      stat_gt_overrides.json and are applied automatically by
      generate_stat_inputs.py (see §5.3) — no manual re-application step.

      After the session, test_stat_ocr_v0_1_1.py writes
      tests/outputs/daily/stat_v0_1_1.json (entries where v0_1_1 diverged
      from GT, grouped by source image) plus failing crop PNGs, unless
      --no-save-failing-crops is passed.

   --- tests/test_score_pipeline.py ---
      detect_blob() vs expected score for each entry in
      tests/inputs/weekly_scores/manifest.json.  Parametrized by key.
      Entries with a missing crop PNG are skipped; add crops and rebuild
      templates (score_detect.py --build) to activate them.
      A failure indicates the score blob pipeline regressed on that crop.


5.5.  Other scripts
      (diagnostic, benchmarking, experimental -- not part of the main workflow)

   Report timestamp convention: every generated
   report below (report_*.txt, pct_fft_ground_truth.py, --verify console
   output) stamps a "Generated: <ISO 8601 local time>  (run start)" line --
   the moment the script began, not when it finished.  Use it to tell
   whether a report predates a template/asset rebuild (compare against
   that file's mtime), not to gauge run duration.

   debugs/score_detect.py
      Benchmark Tesseract vs blob score pipeline across the weekly score set.
      Writes report_tesseract.txt, report_blob.txt, report_summary.txt to
      tests/outputs/weekly_scores/.  --build rebuilds templates only.
         python debugs/score_detect.py             # benchmark both pipelines
         python debugs/score_detect.py --build     # rebuild templates only

   debugs/debug_layout.py   Annotate weekly GS column detection for visual diagnosis.
   debugs/debug_header.py   Annotate daily GS header/stats crop regions.
   debugs/render_debug.py   Render a weekly GS CSV as a visual icon grid.

   debugs/debug_gabor_features.py
      Tabular per-digit debug image for gfl2/stat_ocr_v0_2_0.py's spatial
      features -- one row per digit ('0'-'9'), columns for the raw crop,
      binarized crop, normalized 12x20 classifier input, each Gabor
      orientation's response heatmap (using the CURRENTLY SHIPPED kernels
      from assets/fonts/gabor_calib.json), the '(' / ')' paren template
      overlays, and bar charts of the hist (64-bin) and ring (8-bin)
      feature values.  Every heatmap/overlay/bar chart shares ONE scale
      across the whole table (computed in a first pass over all 10
      digits) rather than normalizing each cell independently -- an
      earlier per-cell-normalized version visually erased the exact
      cross-digit magnitude differences the table exists to show (see
      docs/takeaways.txt #49 for the full story).
      Complements calibrate_gabor.py's real-pipeline accuracy validation
      with a UNIT-level visual check -- guards against "double negative"
      bugs (a defect in one stage silently canceled out by a defect in
      another) that an end-to-end accuracy number can't surface.
         python debugs/debug_gabor_features.py
         python debugs/debug_gabor_features.py --images single/a.png single/b.png

   gfl2/stat_ocr_v0_1_0.py (--build / --verify)
      --verify: compare blob pipeline vs Tesseract GT across a set of images.
      Outputs a per-cell accuracy table; --debug saves annotated panel PNGs.
      --build: rebuild assets/fonts/stat_pct.py + stat_val.py from Tesseract-
      labelled crops.
      GT overrides: stat_gt_overrides.json is applied by BOTH --build and
      --verify (docs/known_issues.txt §15 — a --verify-only override could
      never fix a template already contaminated by the same bad label at
      build time).  assets/builders/build.py, which can also rebuild these
      same two template files via its own training pass, applies the same
      overrides through the shared build_templates() helper.
      Tesseract GT cache: --build and --verify both auto-load
      tests/inputs/daily/tess_gt_cache.py (debugs/build_tess_gt_cache.py) if
      present, skipping live Tesseract for every cell already labelled there
      — pass --no-gt-cache to force live Tesseract regardless (e.g. to check
      the cache hasn't gone stale after re-cropping single/*.png).
         python -m gfl2.stat_ocr_v0_1_0 --build  --images "single/*.png"
         python -m gfl2.stat_ocr_v0_1_0 --verify --images "single/*.png"
         python -m gfl2.stat_ocr_v0_1_0 --verify --images "single/*.png" --debug

   gfl2/stat_ocr_v0_1_1.py (--build / --verify)
      Full duplicate of gfl2/stat_ocr_v0_1_0.py's blob classifier, normalizing
      glyphs by aspect-preserving padding instead of direct-stretch resize
      (docs/known_issues.txt §15).  Own template files
      (stat_pct_padded.py/stat_val_padded.py) and own GT-override wiring;
      never touches the v0_1_0 templates.  Promoted from debugs/ to
      gfl2/ (docs/decisions.txt decision 47 addendum) so it can be selected
      at runtime via `main.py --stat-ocr-engine v0_1_1` — v0_1_0
      remains the default.  Same Tesseract GT cache / --no-gt-cache support
      as gfl2/stat_ocr_v0_1_0.py above.
         python -m gfl2.stat_ocr_v0_1_1 --build  --images "single/*.png"
         python -m gfl2.stat_ocr_v0_1_1 --verify --images "single/*.png"

   gfl2/stat_ocr_v0_2_0.py (--build / --verify)
      FFT+Gabor+paren+ring+loop+vrun nearest-centroid exploration variant
      (docs/known_issues.txt §15).  pct-line only — val is a real no-op
      stub, not selectable via main.py --stat-ocr-engine.  Own template
      file (stat_pct_fft.py, no val file).  --verify also reports per-cell
      classify timing mean/stdev/cv, the primary thing this exploration is
      tracking, plus a full gfl2.timing.pipeline_summary() tree (one
      TimerStack per cell) breaking pct/classify down into
      feature_extraction (itself broken into hist/gabor/paren/ring/loop/
      vstroke/hbar sub-spans) and agent_a_gpr/agent_b_hist — the same
      hierarchical convention gfl2/stat_ocr_v0_1_0.py's real production runs use,
      not a separate profiling script (docs/decisions.txt #58).  Same
      Tesseract GT cache / --no-gt-cache support as the other two.  An 8-sector Fourier "wedge" feature was tried and
      ablated (measured individually strong) but disabled by explicit
      decision — kept, unused, in _wedge_bin_map()/_wedge_energies()
      rather than deleted.  '(' / ')' curve-template correlation and an
      8-band radial "ring" FFT-energy feature were added afterward and
      kept active — paren is chirality-sensitive (unlike every other
      FFT-magnitude feature here).  The classifier is a TWO-AGENT design,
      not one nearest-centroid lookup over the full vector: Agent A
      (gabor+paren+ring+loop+vrun, own scale, margin gate 0.15) is tried
      first; Agent B (the 64-bin histogram, z-score normalized on its own,
      its own independently-tuned margin gate 0.05) is only consulted when
      A is unsure.
      2026-07-05: gabor_0 (vertical orientation) REMOVED — measured fully
      redundant for '4'/'7' (excluding it changed zero real decisions) —
      replaced by a purpose-built isolated (background-flanked) vertical-
      run feature (vrun, MAX_STROKE_W=6, calibrated to the corpus's
      measured stroke width).  loop_top/loop_bot curve templates ADDED,
      a '9'/'6'-targeted partial-arc pair (paren's full-height arc landed
      near-neutral on '9'; loop uses a shrunk, off-center ellipse instead).
      Cell-level pct accuracy: 90.1%/93.2% (without/with pair-tiebreak,
      77-dim gpr) -> 97.2%/97.2% (79-dim gpr, now IDENTICAL with/without
      pair-tiebreak — the flat classifier rarely lands on the {'4','7'}
      top-2 anymore).  See docs/known_issues.txt §15's 2026-07-05 entry for
      the full investigation trail AND two flagged-but-unresolved concerns
      (a new dominant '1'/'7' + '0'/'8' confusion pattern in the remaining
      errors; a structural anomaly on gm_d_20250908 col3 cells) — neither
      was root-caused at the time (docs/known_issues.txt §17, §18).
      2026-07-05 (same day, follow-up): vrun REPLACED by vstroke (2D-
      sliding, single-sided, punished matched filter targeting '1'/'4' vs
      '7' — see docs/known_issues.txt §19), and hbar_top/hbar_bottom ADDED
      (same mechanism transposed, targeting '2'/'4'/'5'/'7', two SEPARATE
      dimensions per this module's own paren_(/paren_) convention — never
      merged via a per-glyph max, which was tried and rejected).  gpr is
      now 17-dim (81-dim total with hist).  Cell-level pct accuracy:

1.2.  Daily Gunsmoke

   Reports daily challenge results. No `owner` info. The image may contain
   one or two reports side-by-side (each titled "Challenge Points").

   Report layout (per panel):

      +-------------------------------------------------------------------------+
      | Challenge Points (dark header bar)               Score (right-aligned)  |
      +-------------------------------------------------------------------------+
      | * Damage dealt XXXK  /  * Damage taken XXXXX  /  * Combat turns N       |
      +-------------------------------------------------------------------------+
      | Deployed Units    Damage Dealt    Stability    Damage Taken   Healed     |
      +----------+--------+-----------+-------------+-------------+-------------+
      | `doll`   | `doll` | pct %     |  pct %      |  pct %      |  pct %     |
      | frame    | name   | value     |  value      |  value      |  value     |
      | (map)    | (OCR)  | (OCR)     |  (OCR)      |  (OCR)      |  (OCR)    |
      +----------+--------+-----------+-------------+-------------+-------------+
      (5 doll rows per report)

      Output format: JavaScript constant accumulated into daily_gunsmoke.js.
   Identified by (filename, report_idx) — re-running the same image is a no-op.

   Format:
      const DAILY_GUNSMOKE = [
        ["gm_d_20250929",1,4635,"2263K",39170,7,[
          ["Qiongjiu",  38.97,882107,24.22,186,14.58, 5716, 0,   0  ],
          ...
        ]],
        ["gm_d_20250929",2,3876,"1409K",54070,7,[...]]
      ];

   Each top-level element: [filename, report_idx, score, dmg_dealt_total,
     dmg_taken_total, combat_turns, [doll_rows]]
   Each doll row: [dollName, dmg_dealt_pct, dmg_dealt_val,
     stab_pct, stab_val, dmg_taken_pct, dmg_taken_val, healed_pct, healed_val]

   Score extraction (header bar):
      The score crop is anchored to the medal icon in the right 25% of the
      header bar.  The leftmost bright blob in that region is treated as the
      medal; the score crop starts immediately to its right (~90px wide,
      scaled proportionally to one doll frame width).  Falls back to a static
      fraction (SCORE_X0=0.920) if no medal blob is detected.

   CLI:
      python main.py <folder/> --pattern daily_gunsmoke            # folder batch
      python main.py <image.png> --pattern daily_gunsmoke          # single image
      python main.py <image.png> --pattern daily_gunsmoke \
          --output path/to/daily_gunsmoke.js
      python main.py <folder/> --pattern daily_gunsmoke \
          --no-save-tess-crops                 # suppress crop PNGs on tess fallback
      python main.py <image.png> --pattern daily_gunsmoke \
          --stat-ocr-engine v0_1_1              # use gfl2/stat_ocr_v0_1_1.py instead
                                                 # of the default v0_1_0 stat_ocr engine
      python main.py <image.png> --pattern daily_gunsmoke \
          --stat-ocr-engine v0_1_0 --stat-templates padded
                                                 # cross-check: v0_1_0 classifier
                                                 # against v0_1_1's templates
      python main.py <image.png> --pattern daily_gunsmoke \
          --stat-ocr-engine v0_3_0              # use gfl2/stat_ocr_v0_3_0.py (pct-line AND
                                                 # val-line, decisions.txt #91) -- val comes
                                                 # from classify_val() directly; no Tesseract
                                                 # call unless --stat-tess-fallback is also
                                                 # passed (e.g. for a residual classifier miss).
                                                 # ALSO selects gfl2/score_ocr_v0_3_0.py for the
                                                 # header SCORE field (known_issues.txt §33,
                                                 # decisions.txt #85-#87) -- fixes a real
                                                 # silent-digit-drop bug in the shared
                                                 # pipeline via its own adaptive-threshold
                                                 # segmentation + classify_score() tree (no
                                                 # internal Tesseract fallback; 100.0% glyph /
                                                 # 99.4% whole-score accuracy on single/*.png);
                                                 # AND gfl2/header_ocr_v0_3_0.py for the header
                                                 # STATS ROW (dealt/taken/turns,
                                                 # known_issues.txt §34, decisions.txt #89) --
                                                 # 100.0% glyph accuracy; v0_1_0/v0_1_1/v0_2_0
                                                 # keep the original score/stats-row pipelines
                                                 # unchanged.
      python main.py <image.png> --pattern daily_gunsmoke \
          --stat-ocr-engine v0_3_0 --stat-tess-fallback
                                                 # same, but fill val via the existing
                                                 # Tesseract psm6/psm4 fallback (slow --
                                                 # every cell needs it, not just rare misses)

   --stat-tess-fallback / --no-stat-tess-fallback (NEW, 2026-07-11,
   decisions.txt #78): governs whether _extract_stat_cell falls back to
   Tesseract (psm6, then psm4) when a stat-cell engine leaves pct or val
   as None.  DEFAULT OFF for every engine, including v0_1_0/v0_1_1 --
   a real behavior change (see decisions.txt #78 for the full rationale
   and the tradeoff this accepts for v0_1_0/v0_1_1's own rare
   genuine blob misses).  Threaded through gfl2.patterns.daily_gunsmoke's
   parse()/_extract_doll_rows()/_extract_stat_cell(), each defaulting to
   True at the LIBRARY level (unchanged for any caller other than
   main.py's own CLI, e.g. existing tests) -- only main.py's own argparse
   default is off.  Added specifically because gfl2/stat_ocr_v0_3_0.py's
   val-line was, at the time, a real no-op stub that always returned None
   (since closed, decisions.txt #91 -- classify_val() now reads val
   directly): with the old always-on fallback, selecting --stat-ocr-engine
   v0_3_0 forced a ~300ms Tesseract call on EVERY stat cell (not just a
   genuine blob miss), turning a ~0.4s image into an 15-19s one for zero
   accuracy benefit over just leaving val as null.  The flag itself stays
   useful post-#91 as an opt-in backstop for classify_val()'s own residual
   misses, at the same per-cell cost.


1.3  Shared output module: gfl2/dg_output.py

   Shared utilities for daily_gunsmoke.py.

   JS model:
      DollRow       — per-doll stat dataclass
      ReportEntry   — one parsed report (header + doll list)
      save_js(entries, path)
                    — append new entries to <path>, deduplicating by
                      (filename, report_idx).  Creates the file if absent.

                    — save portrait to assets/dolls/_<Name>.png.
                      Returns "new" | "upgraded" | "variant" | "skip".
                      Deduplicates via pHash; upgrades if borrow indicator
                      is absent in the new crop but present in the stored one.

   Name OCR utilities:
      _get_doll_name_ocr()  — lazy-load DollNameOcr classifier
      _known_doll_names()   — names from assets/dolls/
      _fuzzy_correct(name)  — Levenshtein snap to nearest known name
      flush_name_templates() — write accumulated EMA template updates
