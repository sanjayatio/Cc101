                  GFL2 Parser — Technical Design


0.  Stat-OCR engine naming conversion table

    The four `--stat-ocr-engine` choices were originally named after their
    role/technique (production/padded/fft/dp).  They were renamed to a
    version-string scheme (the "dp" name specifically was flagged as
    misleading once most of its tree stopped using cv2.approxPolyDP) so each
    engine's identity is stable regardless of which technique it happens to
    use internally.  The rename was done ONE ENGINE AT A TIME, oldest first,
    to keep each step's blast radius small (decisions.txt #96).

       old name    new name   module file                    status
       ─────────   ────────   ────────────────────────────    ─────────────
       production  v0_1_0     gfl2/stat_ocr_v0_1_0.py          DONE
       padded      v0_1_1     gfl2/stat_ocr_v0_1_1.py          DONE
       fft         v0_2_0     gfl2/stat_ocr_v0_2_0.py          DONE
       dp          v0_3_0     gfl2/stat_ocr_v0_3_0.py          DONE
                              (+ gfl2/score_ocr_v0_3_0.py,
                               gfl2/header_ocr_v0_3_0.py)

    The --stat-templates VARIANT flag (a template-file selector, independent
    of --stat-ocr-engine) still accepts 'padded' as a variant name, and the
    physical template files (assets/fonts/stat_pct_padded.py/
    stat_val_padded.py) are still named "padded" -- that flag's variant
    namespace was deliberately left untouched by this rename, since it isn't
    1:1 with the engine identifiers (e.g. `--stat-ocr-engine v0_1_0
    --stat-templates padded` mixes engine and templates on purpose).

    docs/known_issues.txt, docs/decisions.txt, docs/takeaways.txt, and
    docs/action_items.txt are permanent, append-only historical records
    (CLAUDE.md's documentation numbering conventions) and are NOT rewritten
    when an engine is renamed -- every existing entry there keeps referring
    to the OLD name it used at the time it was written (e.g. "gfl2/
    stat_ocr.py", "StatOcr", "--stat-ocr-engine production").  Use this table
    to translate an old name encountered in those files to its current one.
    Only this file (docs/technical_design.txt), CLAUDE.md, reference.txt,
    and code/tests are kept current with the new names as each engine is
    renamed.

2.  Module responsibilities

   2.1  layout.py

        parse_rows(image) -> list[Row]

        Scans the image top-to-bottom for dark horizontal bands. Thick
        bands are date separators (OCR'd). Thin bands are row dividers.
        Content between bands is split into Row objects carrying the date
        label inherited from the most recent date separator.

        Row.crop(col) -> np.ndarray | None

        Returns the sub-image for a named column using fixed width ratios.
        The 'name' column additionally clips to the top 60px to avoid the
        'Decisive Battle' badge below the name text.

   2.2  asset_mapper.py

        AssetMapper(category).translate(frame) -> str | None

        Three-pass lookup:
          Pass 1  pHash distance <= 6    → return name (fast, same-session)
          Pass 2  HSV histogram corr >= 0.92 → return name (cross-session)
          Pass 3  Unknown                → save GUID or dedup-skip

        _make_mask(h, w) -> np.ndarray
        Builds the histogram mask: excludes optional icons, keeps element
        icon and main face region.

        _icon_score(img) -> int
        Counts optional icons in a frame. Used by _maybe_upgrade() to
        decide whether to replace the stored reference with the current
        (cleaner) frame.

   2.3  weekly_gunsmoke.py

        parse(image) -> list[GunsmokRecord]

        Calls parse_rows(), then for each row: OCR the owner name and score,
        map the buff and five doll frames via AssetMapper.  Each doll column
        crop is passed through normalize_portrait() (dg_output) before
        translate() so weekly crops are 128×128 and share the assets/dolls/
        library with the daily pipeline.

        GunsmokRecord.to_csv_row()

        Joins field values with commas. Leading '_' is stripped from all
        values so '_QiongJiu' becomes 'QiongJiu' in the output.

   2.4  main.py

        CLI: python main.py <image> [--pattern P] [--output O]

        Default output path (weekly): <image_stem>.csv in the same
        directory, UNLESS the image resolves under tests/inputs/ (a
        committed test fixture) -- then _default_weekly_output()
        redirects to tests/outputs/weekly_gunsmoke/<image_stem>.csv
        instead, mirroring the tests/outputs/daily/ convention.  Avoids
        leaving generated CSVs next to committed fixture PNGs
        (docs/decisions.txt §44).
        Tesseract path is auto-configured by gfl2/__init__.py at import
        time (see §7.15); main.py does not need to handle it directly.


3.  Asset management workflow

   First run (no references):
      1. Run main.py on any image.
      2. Unknown buffs/dolls are saved as GUID PNGs in assets/.
      3. User opens assets/buff/ and assets/dolls/, views each crop,
         renames it to the correct name (prefix with '_' for dolls).
      4. Re-run: all renamed assets are now matched.

   Rebuild from scratch (wrong crops):
      1. Run rebuild_assets.py <image> to clear and re-crop with current
         column layout. Saves row##_buff.png / row##_doll{1-5}.png.
      2. Identify each crop, rename to correct name.

   Adding a new doll:
      1. Run main.py on an image containing the new doll.
      2. A GUID is saved in assets/dolls/.
      3. Rename the GUID to '_DollName.png'.


4.  Matching pipeline detail

   Same session (e.g. re-running same image):
      pHash distance = 0 → matched instantly, no histogram computed.

   Cross-screenshot same doll, same Lv. tier:
      pHash distance typically 14-18 (fails pHash gate) →
      HSV histogram correlation typically 0.96-0.99 → matched.

   Cross-screenshot same doll, different Lv. tier (e.g. Lv.60 vs Lv.90):
      pHash distance high (badge color changes DCT) →
      HSV histogram still 0.96-0.99 because face colors are unchanged →
      matched correctly.

   Doll with borrowed indicator (yellow icon top-right):
      Borrowed region masked out before histogram →
      matched correctly as the underlying doll.

   Doll with optional buff arrows (left side):
      Arrow regions masked out before histogram →
      matched correctly.

   Unknown doll (not in assets/):
      pHash fails, histogram fails, dedup check passes → GUID saved.


5.  Testing

   Regression tests live in tests/ and run with:

      cd gfl2_py
      python -m pytest

   pytest.ini configures test discovery so `pytest` (no arguments) from
   the project root always finds and runs all tests. conftest.py inserts
   the project root into sys.path so `gfl2` is importable regardless of
   working directory.

   conftest.py also patches gfl2.asset_mapper.ASSETS_DIR to a temp seed
   directory ($TEMP/gfl2_test_seeds/) and seeds it with normalized portraits
   (via normalize_portrait) cropped from the reference images before any test
   runs.  This keeps test assets isolated from the live assets/dolls/ tree and
   ensures seeds use the same 128×128 format as production queries.

   test_weekly_gunsmoke.py covers:
      - Row count per image
      - Per-row assertions on: date, buffName, doll1-5, score
      - Two reference images: gm_250801.png (8 rows) and gm_250730.png (4 rows)
      - Cross-screenshot matching (gm_250730 uses Lv.90; references are Lv.60)
      - Borrowed doll (Tololo appears with yellow indicator in several rows)
      - Unknown doll (Vector in gm_250730 row 3)

   test_daily_gunsmoke.py covers (requires single/gm_d_20250929.png):
      - Panel count (2)
      - Per-panel assertions on: score, dmg_dealt_total, dmg_taken_total,
        combat_turns, doll_count
      Ground truth from reference.txt §1.2.
      This is an end-to-end parse test; it exercises panel splitting, header
      crop geometry, score blob detection, and stats-row blob detection in one
      shot, making it sensitive to panel-bounds regressions and OCR threshold
      issues that pre-cropped stat tests cannot detect.

      Also covers (docs/decisions.txt #98): timer-span/wall_clock_s
      completeness for main.py's own daily-gunsmoke call sites (see
      §7.20's REGRESSION COVERAGE note) -- the only tests in this file
      that call main._process_daily_single/_process_daily_folder
      directly instead of gfl2.patterns.daily_gunsmoke.parse().

   conftest.py also patches gfl2.dg_output._save_doll_portrait to a no-op
   after seeding, preventing daily-GS parse() calls inside test fixtures from
   overwriting seeded portraits or creating new unknown GUID crops.

   When adding a new reference image to the test suite:
      1. Copy the image to tests/
      2. Run the parser manually to get ground-truth values
      3. Add an Expected list and a test class to test_weekly_gunsmoke.py

   Before running tests on Windows after editing gfl2 source, run:

      python compile_gfl2.py

   This force-recompiles all gfl2 modules using CHECKED_HASH invalidation
   mode, making .pyc files immune to cross-platform mtime issues that can
   cause stale bytecode to be silently loaded (see known_issues.txt).


7.  New modules (added post-initial design)

   7.15  gfl2/__init__.py  (Tesseract auto-configuration)

        At package import time, checks whether `tesseract` is findable via
        shutil.which().  If not, and if the Windows default install path
        (C:\Program Files\Tesseract-OCR\tesseract.exe) exists, sets
        pytesseract.pytesseract.tesseract_cmd to that path.

        This runs once before any submodule imports pytesseract, so
        layout.py, buff_ocr.py, weekly_gunsmoke.py, and daily_gunsmoke.py
        all benefit without any per-module path handling.  The guard is
        no-op on Linux/macOS where tesseract is typically on PATH.


   7.1  buff_ocr.py

        recognize_buff(crop) -> str | None

        OCR-based buff name recognition replacing the earlier template/HSV-
        histogram approach. Buff icons have dark backgrounds with
        monochromatic art — color cannot distinguish them. Text in the buff
        icon area is always readable, making OCR the reliable approach.

        Algorithm:
          1. Multi-threshold brightness OCR: run Tesseract at several
             binarization thresholds (threshold values sweep from dark to
             light) to maximise the chance of extracting any text at all.
          2. CamelCase extraction: from each OCR result, extract runs of
             uppercase-leading words (e.g. "SpeedBuff", "AttackUp").
          3. Majority-suffix voting: across all threshold runs, collect the
             word-suffix fragments and pick the candidate that appears most
             often. This tolerates partial misreads at individual thresholds.
          4. Y-position word ordering: words are sorted by their detected
             Y-coordinate before joining, so multi-line buff names are
             assembled top-to-bottom regardless of Tesseract output order.
          5. Name validation (_is_valid_name): accept only results where
             every word is >= MIN_WORD_LEN (4) characters and there are at
             least MIN_THRESHOLDS (1) agreeing votes. Rejects noise fragments.
          6. Auto-save: when a valid name is produced and no reference crop
             exists for it yet, the current crop is saved to assets/buff/.

        Constants:
          MIN_THRESHOLDS = 1    minimum agreeing threshold runs to accept
          MIN_WORD_LEN   = 4    minimum characters per word

   7.2  gfl2/trace.py

        @trace decorator

        Wraps any function to log: function name, caller name, and elapsed
        time (seconds, 3 d.p.) to stderr. Activated only when the
        environment variable GFL2_TRACE=1 is set; zero overhead otherwise.

        Usage:
          from gfl2.trace import trace

          @trace
          def my_function(...):
              ...

        Intended for profiling OCR calls during diagnosis of timing-related
        bugs (see known_issues.txt — blank score issue).

   7.3  compile_gfl2.py

        Force-recompiles every .py file in the gfl2/ package using
        py_compile with invalidation_mode=CHECKED_HASH. This writes a
        content-hash into the .pyc header so Python validates bytecode
        against file content rather than mtime. Eliminates stale-bytecode
        problems that arise when files are edited via a cross-platform
        mounted filesystem (Linux sandbox writing Windows files).

        Replaces the earlier clean_cache.py (which only deleted .pyc files,
        requiring a subsequent import to regenerate them under the default
        mtime mode).

        Run before any test/production run if gfl2 source was edited outside
        of native Windows Python.

   7.4  render_debug.py (Weekly Gunsmoke, redesigned)

        Reads a Weekly Gunsmoke CSV and renders a compact visual image for
        spot-checking parsed output without reopening the raw screenshot.
        Not applicable to Daily Gunsmoke (different output format).

        Layout:
          - Date label rendered above each buff icon (not as a full-width
            banner, which obscured adjacent columns).
          - Owner and score rendered in the rightmost column.
          - Buff and doll icons loaded from assets/; grey placeholder when
            asset is missing.
          - Column boundaries detected via binarization (date band threshold
            lowered from 40 to 30 to catch thin separator bands reliably).

        Usage: python debugs/render_debug.py <csv_path>
        Output: <csv_stem>_debug.png alongside the CSV.

   7.5  parse() batching in weekly_gunsmoke.py

        All Tesseract work (score OCR + buff name OCR) is batched into a
        first pass over all rows before any buff_ocr auto-save calls are
        made. This decouples the OCR phase from filesystem writes, preventing
        Tesseract process-level interference that was observed on Windows
        when a new buff asset was saved mid-parse (see known_issues.txt).

        Order of operations in parse():
          1. parse_rows(image)              → row list
          2. For each row: _ocr_score()     → scores[]
          3. For each row: buff_ocr()       → buff_names[] (no saves yet)
          4. For each row: asset auto-save  → write any new buff PNGs
          5. For each row: doll matching    → doll names
          6. Assemble GunsmokRecord objects


   7.6  daily_gunsmoke.py

        parse(image) -> list[DailyGunsmokRecord]

        Handles "Challenge Points" screenshots containing one or two panels
        side-by-side. Registered as pattern "daily_gunsmoke".

        Panel split algorithm (hybrid):
          1. _split_panels(image): find the brightest column in the middle third
             of the header bar; slice image at that x → left/right sub-images.
             This gives correct image bounds regardless of frame positions.
          2. _find_all_frames(image): single contour scan of the full image;
             square-ish blobs filtered by size (≥ 60% of max area) are frames.
          3. _group_frames_into_panels(frames): cluster by x-position; gap > 50px
             between adjacent frame x-values marks a new group (panel).
          4. Frame coordinates are translated to panel-local origin and passed to
             _extract_header and _extract_doll_rows, skipping any redundant
             internal _find_frames call.
          Using _split_panels for image slicing is critical: frame x-positions
          sit at the LEFT EDGE of each panel, so a midpoint derived from frame
          positions falls inside the left panel's content, not at the visual
          boundary between panels.

        Vertical zone detection (fractions of image height):
          Header bar (title + score): 0.010 – 0.082
          Stats row (totals):         0.082 – 0.170
          Table header (ignored):     0.170 – 0.234
          Doll rows (5 equal):        0.234 – 1.000

        Column proportions (fractions of each panel width):
          Portrait (ignored):    0.000 – 0.083
          Name:                  0.083 – 0.220
          Col1 (dmg dealt):      0.192 – 0.384
          Col2 (stability):      0.376 – 0.575
          Col3 (dmg taken):      0.575 – 0.767
          Col4 (healed):         0.767 – 1.000
          Score (header only):   0.820 – 1.000

        OCR strategy:
          Score (blob pipeline, primary):
                  _header_isolate_blobs() binarizes at THRESH_VAL=150 and collects
                  digit blobs.  If any blob is wider than NORM_W×1.3 (≈26 px,
                  indicating two merged digits), retries at THRESH_VAL+5/+10/+15/+20
                  using the minimum increment that yields more blobs, then splits the
                  merged blob using sub-blob positions from the higher threshold.
                  Interior holes (RETR_CCOMP) are counted per blob (n_inner).
                  _read_bright_number() classifies each blob by projection correlation;
                  if the best match is a no-hole digit ('1','2','3','5','7') but the
                  blob has n_inner ≥ 1 interior hole, overrides to the best hole-digit
                  ('0','6','8','9') scoring ≥ 90% of PROJ_CORR_MIN (disambiguates
                  '5' vs '6' when templates were built from a different font size).
                  Falls back to Tesseract (PSM 7, multi-threshold sweep 150→190) if
                  the blob pipeline returns None or a partial result.
          Stat cells (pct + raw value):
                  8× upscale, trim bottom 15% (removes progress bar), PSM 6.
                  If the extracted numeric value is <= 2 digits, retry the
                  same crop with PSM 4 — edge-hugging short numbers are
                  missed by PSM 6's block assumption.
          Doll name:  8× upscale, PSM 7; strip any leading tokens shorter
                  than 3 characters (rank-icon noise, e.g. "s Nikketa" →
                  "Nikketa").
          Stats header (totals row):  8× upscale, PSM 6; regex-extract
                  dmg_dealt_total, dmg_taken_total, combat_turns.

        Validation (reference images):
          gm_d_20250929.png (2283×696): 10/10 doll rows correct.
          gm_d_20250928.png:            10/10 doll rows correct.
          Dolls recognised: Qiongjiu, Sharkry, Qiuhua, Vector,
          Centaureissi, Nikketa, Tololo, Makiatto, Colphne, Springfield.


   7.7  assets/builders/build.py  (unified Daily Gunsmoke builder)

        Replaces the former populate_doll_assets.py and build_header_templates.py.
        Reads each image once and extracts all three outputs in a single panel pass:
          - Doll portraits           →  assets/dolls/_Name.png
          - Header-stat digit templates  →  assets/fonts/stat_header.py
          - Stat-cell pct/val templates  →  assets/fonts/stat_pct.py + stat_val.py

        Per image: cv2.imread → _split_panels → per panel: _find_frames once,
        then the portrait, header-template, and stat-cell paths all share that
        same frames list.  This eliminates the duplicate imread / _split_panels /
        _find_frames calls that existed when these were run as separate scripts.

        Portrait path (per frame):
          _crop_portrait (dg_output) → Tesseract name OCR → _fuzzy_correct →
          _save_doll_portrait (dg_output, pHash dedup + borrow-indicator upgrade).

        Header-template path (per panel, using frames[0] as anchor):
          _header_crop → Tesseract GT string → _collect_samples (blob features) →
          accumulate into per-digit buckets → _avg_features → JSON.

        Stat-cell path (per frame row × 4 columns, using the SAME frames list):
          _frame_col_cell → Tesseract GT (pct, val) via _tess_label_cell →
          appended to a flat stat_training list, with a "source" key in the
          same f"{stem}_p{pi+1}_r{ri}_{cname}" format gfl2.stat_ocr_v0_1_0._collect_cells
          uses — required so gfl2.stat_ocr_v0_1_0.build_templates() (called once at
          the end, after all images/panels are processed) can match
          stat_gt_overrides.json entries against these crops too.  Without a
          matching "source" key, a known-bad Tesseract label collected here
          would silently bypass the override and re-contaminate the template
          on every rebuild — see docs/known_issues.txt §15 and decisions.txt §29.

        Usage:
          python assets/builders/build.py <folder>
          python assets/builders/build.py <image.png>
          python assets/builders/build.py "single/*.png" -v

        assets/builders/rebuild_assets.py is a separate, Weekly Gunsmoke-only
        emergency tool (uses gfl2.layout.parse_rows, not Daily GS code) for
        clearing and re-cropping buff/doll assets from a reference screenshot.
        It is not part of the normal Daily GS build flow.


   7.8  gfl2/stat_ocr_v0_1_0.py

        StatOcrV0_1_0.load() -> StatOcrV0_1_0

        Loads character templates from assets/fonts/stat_pct.py + stat_val.py.
        Templates store averaged Hu moments, 1D vertical projection, and 1D
        horizontal projection for each character in two size classes (pct_line
        ~20px tall digits, val_line ~13px tall digits).

        build_templates(training, verbose=True, gt_overrides=None) applies
        stat_gt_overrides.json (auto-loaded if gt_overrides is left None)
        to each training item's pct/val BEFORE bucketing, matched by the
        item's "source" key.  This is the single point every build path
        shares (gfl2/stat_ocr_v0_1_0.py's own --build CLI and
        assets/builders/build.py's independent stat-cell collection both
        call this function), so a known-bad Tesseract label can't survive a
        rebuild by going through the "wrong" entry point — see
        decisions.txt §29's 2026-07-03 update.

        _collect_cells(image_paths, tess_only, gt_cache, excluded_cells)
        auto-loads stat_excluded_cells.json (via _load_excluded_cells())
        and drops any cell whose "source" key matches BEFORE any labeling
        or classification runs — for cells whose SOURCE PIXELS are known
        corrupted (not a wrong label; there is no correct label to
        recover), e.g. a mid-animation screenshot capture (decisions.txt
        #56).  gfl2/stat_ocr_v0_2_0.py imports this function directly and
        inherits the exclusion automatically; gfl2/stat_ocr_v0_1_1.py
        carries its own full duplicate of _collect_cells (§7.16) and needed
        the identical parameter added there separately.

        StatOcrV0_1_0.read(cell, timer=None) -> tuple[str | None, str | None]

        Reads a stat cell crop and returns (pct_string, val_string). The
        algorithm:
          1. _split_lines(): find contours, group by y-centroid gap (largest gap
             separates pct from val line), apply _filter_y_outliers on each group.
          2. _classify(norm, templates, v_primary=False) reduces a normalised
             glyph to a single character in phases, each narrowing or
             short-circuiting the next:
               a. inner-blob hole-count pre-filter (decisions.txt §30) —
                  categorical for '8' (2 holes) vs. '5' (0 holes); only
                  applied when the query shows >=2 holes, since 0/1-hole
                  counts are unreliable at this resolution.
               b. 2-vs-3 bottom-row-width discriminator (decisions.txt §46) —
                  categorical for '2' (full-width flat bottom stroke) vs.
                  '3' (curls inward); holes can't separate this pair since
                  neither digit has one.
               c. projection scoring: combined (v_corr + h_corr)/2 correlation
                  against every surviving template; v_primary=True (pct
                  glyphs) can return early on a decisive v-only match.
               d. clear-winner shortcut (decisions.txt §31/35-area) when the
                  top combined score and its gap over the runner-up both
                  clear a lower bar, avoiding an unreliable Hu tiebreaker.
               e. Hu-moment (top/bottom half) fallback for whatever's left —
                  known unreliable on the hardest cases (known_issues.txt §14).
             Returns '?' if confidence never clears PROJ_VERY_LOW.

        When timer is provided, sub-spans are emitted under the caller's active
        span: pct/binarize, pct/blobs, pct/extract, pct/classify, and the val
        equivalents.  Under each classify span, three synthetic child spans are
        injected (inner_blobs, projection, hu_fallback) using a perf_counter
        accumulator rather than per-glyph context managers, to avoid overhead
        in the tight classification loop.  (The 2-vs-3 discriminator's own
        cost is folded into the inner_blobs accumulator bucket rather than
        given a fourth bucket — it's a few numpy ops, not worth a separate
        timing category.)

        Timing profile (88 images / 3256 cells, June 2026):
          val/classify    54%  of stat_cell/blob  → projection: 98% of classify
          pct/classify    44%  of stat_cell/blob  → projection: 98% of classify
          all other steps  <2%  combined
        The hot path is _proj_corr (np.corrcoef per template per axis per glyph).
        Next optimization target: vectorize template scoring into a matrix op.

        _find_percent_x_start(blobs) -> int | None  (rewritten 2026-07-11,
        decisions.txt #79) identifies where the pct line's digit sequence
        ends and the trailing '%' sign's sub-blobs begin, so the '%'
        blobs get excluded before classify() ever sees them. Two cases:
        Case A (all three '%' sub-glyphs fused into one wide/square blob)
        is a direct shape check, unchanged. Case B (the more common split
        rendering — top circle + diagonal slash + bottom circle, three
        separate blobs/contours) now scans right-to-left from the
        rightmost blob, merging into the '%' group while each pair of
        adjacent blobs' bounding boxes OVERLAP in x (the diagonal slash's
        box spans wide enough to overlap both circles' boxes even though
        the ink itself never touches — two regions whose ink DOES touch
        would already be one contour, not two blobs), stopping at the
        first pair with a genuine (non-overlapping) gap. This replaced a
        fixed-pixel-offset heuristic (bottom_circle.x - 25px) that was
        silently calibrated to one corpus's typical resolution and
        capture-scale and overshot on a genuinely differently-scaled
        capture (known_issues.txt §18) — the new rule is scale-invariant
        (the SIGN of a relative gap, not an absolute pixel distance), and
        was validated against all 1466 real Case-B splits in single/*.png
        before being trusted. gfl2/stat_ocr_v0_1_1.py carries its own
        full duplicate of this function and needed the identical fix
        ported by hand (decision 47's full-duplication policy — a fix in
        one does not propagate to the other); gfl2/stat_ocr_v0_2_0.py and
        gfl2/stat_ocr_v0_3_0.py both import it directly from this module and
        received the fix automatically.

        UPDATE (2026-07-12, decisions.txt #83, known_issues.txt §32):
        blobs with area < PCT_ANCHOR_MIN_AREA=9 are now dropped BEFORE
        either case runs — a corpus-measured noise-speck floor (the
        smallest genuine blob anywhere in single/*.png, measured with
        fresh per-cell thresholds, is a 3x3=9-area '.' dot). Without it, a
        stray sub-pixel-scale artifact landing to the right of the real
        content could be picked as the "rightmost" blob and corrupt both
        cases (traced via gfl2/stat_ocr_v0_3_0.py's own adaptive per-cell
        threshold cache, whose value is shared/order-dependent across a
        multi-image run — a threshold seeded by an earlier image let one
        such speck cross the ink threshold for a later cell). Same
        full-duplication porting requirement as the fix above — applied
        to gfl2/stat_ocr_v0_1_1.py's copy by hand.

   7.9  gfl2/doll_name_ocr.py

        DollNameOcr — projection-based nearest-neighbour classifier for doll
        names in Daily Gunsmoke images.  Designed to replace Tesseract for
        known doll names, reducing name OCR time from ~176ms to ~1ms.

        Feature extraction (feature(cell)):
          1. Convert name-column crop to grayscale.
          2. Fixed high-threshold binary (≥200 brightness) to isolate the
             bright white name text from the darker game-UI background.
             (Adaptive/Otsu thresholding was rejected: it picks up UI
             decoration elements that span the full crop, producing nearly
             identical feature vectors for all doll rows.)
          3. Find tight bounding box of foreground pixels.
          4. Split bounding box into top / bottom halves.
          5. Resize each half to SIG_WIDTH (64) columns; compute column-wise
             mean → 1-D signature of SIG_WIDTH float values in [0, 1].
          6. Concatenate top + bottom → 2×SIG_WIDTH feature vector.

        Classification (DollNameOcr.classify):
          L2 nearest-neighbour against stored templates.
          Returns the best-match name when dist < MATCH_THRESHOLD (1.8),
          else None (falls back to Tesseract slow path).

        Self-bootstrapping template updates:
          When the Tesseract slow path produces a name (OCR + fuzzy-
          correction), the name crop is accumulated in _NEW_CROPS.
          flush_name_templates() (called from main.py after each batch)
          calls DollNameOcr.update(), which merges incoming crops into the
          template file via exponential moving average (alpha=0.3).
          Effect: first run uses Tesseract; subsequent runs use projection
          for already-seen dolls.

        Mislabelling caveat:
          Templates are built from OCR-labelled crops.  If Tesseract
          consistently misreads a name (e.g. "Sharkry" → "Sharkty"), the
          template is stored under the wrong name.  The projection result
          is passed through _fuzzy_correct() as a belt-and-suspenders fix;
          however, fuzzy correction only snaps to names present in
          assets/dolls/, so the portrait file must also be correctly named.
          Manual fix: rename assets/dolls/_Sharkty.png → _Sharkry.png and
          rename the template entry in assets/doll_names/templates.json.

        CLI:
          python -m gfl2.doll_name_ocr --build daily/     # folder of gm_d_*.png
          python -m gfl2.doll_name_ocr --build img.png --show
          Template file: assets/doll_names/templates.json


   7.11  gfl2/timing.py

        TimerStack — lightweight hierarchical wall-clock timer for single-
        threaded use.  Replaces the flat _T / _record / print_timing_summary
        pattern that was originally in daily_gunsmoke.py.

        Usage:
          t = TimerStack()
          with t.timed("parse"):
              with t.timed("find_frames"):
                  ...
          print(t.root.tree())

        API:
          TimerStack.timed(name) -> ContextManager[Span]
            Push a new Span onto the stack on entry; record elapsed time on
            exit.  Nesting is tracked automatically — each span's children
            are the spans opened while it was on top of the stack.

          Span.tree() -> str
            Format the tree with indentation and elapsed + % of parent.

          Span.total_ms_for(name) -> float
            Sum elapsed ms for all spans named `name` anywhere in the tree.

        batch_summary(image_names, roots) -> str
          Given per-image root Spans, print a one-liner table: total, avg,
          fastest, and slowest image names with timings.  Used by main.py
          in folder mode.

        daily_gunsmoke.py creates a TimerStack per image and wraps every
        significant sub-step in timer.timed().  The root span is named after
        the image filename or stem.

        pipeline_summary(image_names, roots, wall_ms=None, unit="image") -> str
          Aggregates sub-spans across every root into ONE hierarchical
          tree, sorted by total time descending at each level (unlike
          Span.tree(), which prints one root's own tree unaggregated).
          main.py's folder-mode daily run is the original caller (one root
          per processed image). `unit` (added 2026-07-05, decisions.txt
          #58) generalizes the header's noun ("N images" -> "N cells")
          for callers whose roots are per-cell rather than per-image --
          e.g. gfl2.stat_ocr_v0_2_0.verify(), which creates one TimerStack per
          stat cell to report a feature_extraction breakdown
          (hist/gabor/paren/ring/loop/vstroke/hbar) the same way
          gfl2/stat_ocr_v0_1_0.py's real runs report inner_blobs/projection/
          hu_fallback. Backward compatible: existing callers that don't
          pass `unit` are unaffected.

   7.14  score_detect.py (Weekly Gunsmoke score pipeline)

        Dual-purpose module for the Weekly Gunsmoke score-OCR pipeline.
        Not used by Daily Gunsmoke (which uses stat_ocr_v0_1_0.py instead).

        As a benchmark tool:
          python debugs/score_detect.py         — run both pipelines on weekly_scores/
          python debugs/score_detect.py --build — rebuild digit templates only

          Inputs:  tests/inputs/weekly_scores/manifest.json  (crop paths + expected values)
                   tests/inputs/weekly_scores/*.png          (score crop images)
          Outputs: tests/outputs/weekly_scores/report_tesseract.txt
                   tests/outputs/weekly_scores/report_blob.txt
                   tests/outputs/weekly_scores/report_summary.txt  (side-by-side comparison)
                   assets/fonts/score_digits.py  (rebuilt on --build)

        As an importable library:
          make_score_fn(templates_path=None) -> callable
            Returns a score-extraction function with signature (Row) -> str | None,
            suitable for passing as score_fn= to weekly_gunsmoke.parse().
            This is the production integration point: main.py calls make_score_fn()
            when --score-pipeline blob is active (the default).

        Blob/Hu pipeline (same algorithm used in production):
          1. Inverse binary threshold (THRESH_VAL=150) to isolate dark digits.
          2. Contour detection; filter by size (DIGIT_MIN_W/H, DIGIT_MAX_W/H)
             and x-position (MIN_X_DIGIT=30 skips coin icon).
          3. Each blob normalised to NORM_W×NORM_H (20×30 px).
          4. Pass 1: 1D vertical projection correlation vs. templates
             (threshold PROJ_CORR_MIN=0.75); accept if above threshold.
          5. Pass 2: Hu moment chi-square distance fallback
             (threshold HU_THRESHOLD=0.25).
          6. Return joined digit string; None if any digit is unconfident.

        Templates are per-digit averages over all labelled samples in the
        score set.  Rebuild with --build after adding new score crops.

   7.20  gfl2/report.py  (NEW, 2026-07-12, docs/decisions.txt #90)

        Daily Gunsmoke production-run report generator -- writes
        tests/outputs/daily/reports/report_<commit>_<dirty-lines>.py
        after every `main.py --pattern daily_gunsmoke` run (single image
        or folder batch), unconditional, no opt-out flag. A generated
        Python module (META + SECTIONS dicts), same "generated module,
        not JSON" convention as tests/inputs/daily/stat_data.py; filename
        tag duplicated (not imported) from
        debugs/persist_run_result.py's commit_dirty_tag() -- gfl2/
        modules import FROM debugs/, never the reverse.

        META: run-start time (ISO 8601, captured before the first image
        is processed), total wall-clock elapsed, images processed,
        commit/dirty-lines tag, stat-ocr engine used. A dirty tree (>0
        changed lines vs HEAD) gets a WARNING line in the module's own
        docstring -- this should generally be run against a clean commit.

        SECTIONS: one entry per score / header (dealt/taken/turns) / pct
        / val, each with:
          - summary: processed / ok / failed / unknown_glyphs counts.
            "ok" = the fast/blob path resolved cleanly (no '?', no
            fallback needed); "failed" = still None after every fallback;
            "unknown_glyphs" is a GLYPH count (not a cell count) of '?'
            characters seen in the blob's raw, pre-strip output -- a
            single cell's raw string can carry more than one. Recorded
            via one `_record_field(section, raw, final)` call per field,
            added to gfl2/patterns/daily_gunsmoke.py's existing
            _extract_header() (score, stats-row) and _extract_stat_cell()
            (pct, val) -- no change to what either function classifies or
            returns, only a counter alongside it.
          - pipeline: stage / total_s / hits / avg_ms, built by flattening
            every gfl2.timing.Span at every depth across all per-image
            TimerStack roots and filtering by span name per section. pct
            and val share stat_cell/blob + stat_cell/psm6/psm4 (one
            engine.read() / Tesseract call classifies both lines
            together) -- identical rows under both sections by
            construction, not a bug (same pct-vs-whole-engine timing
            distinction as docs/decisions.txt #57).

        Capturing "raw" (pre-'?'-strip) for the header stats-row required
        hoisting a small duplication: `_extract_header()`'s dealt/taken/
        turns block had the same `if X and '?' in X: X = None` stripping
        inline in BOTH its header_ocr and hdr_stat_tmpl branches,
        discarding the raw string before any caller could see it. Moved
        to run once after either branch (also removing the duplication).

        NOT DONE: no regression test for _record_field/
        flush_section_stats/generate_report themselves (action_items.txt
        #35); weekly_gunsmoke has no equivalent report (its fields don't
        map to this section scheme).

        REGRESSION COVERAGE (2026-07-19, docs/decisions.txt #98): the
        span-completeness invariant this file's SECTIONS/pipeline
        breakdown depends on -- every processed image's Span.root.ms
        tracking main.py's own independently-measured wall_clock_s (the
        property known_issues.txt §35's fix established) -- is now
        covered by tests/test_daily_gunsmoke.py's
        test_timer_spans_account_for_wall_clock_single_image/_folder.
        These call main._process_daily_single/_process_daily_folder
        directly (not gfl2.patterns.daily_gunsmoke.parse() alone), since
        two of §35's three original untimed spans (image_load, save_js)
        live in main.py's own call sites, not inside parse(). The NOT
        DONE gap above (generate_report's own SECTIONS/META correctness)
        remains open.

        PER-BRANCH/PER-STAGE INSTRUMENTATION FOR v0_3_0 (2026-07-19,
        docs/known_issues.txt §39, decisions.txt #100): _SECTION_SPAN_NAMES
        had listed pct/binarize, pct/blobs, pct/extract, pct/classify
        (and val/*) since this file was first written, but
        gfl2.stat_ocr_v0_3_0.StatOcrV0_3_0.read()'s `timer` parameter was
        never actually forwarded to _read_line() -- those names were dead
        entries in the mapping, never emitted by anything, until this fix.
        _SECTION_SPAN_NAMES["score"] gained score/binarize, score/blobs,
        score/classify the same way (gfl2/score_ocr_v0_3_0.py's read_score()
        previously had no `timer` parameter at all).

        NOT extended to the new classify()/classify_val() per-LEAF branch
        names (circular_069, skeleton_235, etc., plus skeleton_235's own
        nested skeleton_thin child) -- this is a real, load-bearing
        constraint on this section's design, not an oversight:
        _flatten_spans() merges every Span in the tree BY NAME ONLY,
        globally, regardless of nesting depth or parent. classify() (pct)
        and classify_val() (val) deliberately reuse the SAME short branch
        names for their structurally-parallel leaves, relying on
        gfl2.timing.pipeline_summary()'s _build_agg_tree being
        NESTING-AWARE (it aggregates per-PARENT, so pct/classify's
        "branch" children and val/classify's "branch" children stay
        correctly separate) to keep pct-tree and val-tree costs apart.
        Adding those same names to this flat, name-only mapping would
        silently sum pct-tree and val-tree branch timing into one number.
        The branch/skeleton-thin breakdown is therefore visible via the
        console's pipeline_summary() tree (printed on every folder-batch
        run) but deliberately not mirrored into this file's generated
        SECTIONS -- any future name added to _SECTION_SPAN_NAMES must be
        globally unique across every span in the tree, not merely unique
        within the section it's being added for.


   7.21  gfl2/field_id.py  (NEW, 2026-07-19, docs/decisions.txt #101/#102)

        Two formatters for Daily Gunsmoke field identifiers
        (docs/reading_the_logs.txt §6), deliberately asymmetric:

        `LegacyFieldId` -- READ-ONLY. Parses the existing
        `p<N>_r<N>_col<N>` format (panel/col 1-indexed, row 0-indexed, no
        pct/val disambiguation -- docs/known_issues.txt §40) via
        `.parse(s)`. Has no `__str__`/format method that reproduces a
        legacy string, so nothing can accidentally emit a NEW legacy id
        through it. `.to_v2(line)` converts a parsed instance forward into
        a `FieldId` (row -> row+1), requiring `line` ('pct'/'val') as an
        explicit argument since the legacy format has no way to know which
        one a bare citation meant.

        `FieldId` -- READ-WRITE. `.parse(s)` reads the new `p<N>_<field>`
        format; `.score()`/`.header()`/`.stat_cell()` classmethods plus
        `__str__` build one. Validates 1-indexing and the `score`/`hdr_*`/
        `pct`/`val` vocabulary at construction time, not just at parse
        time, so a caller can't build an invalid v2 id in the first place.

        WIRED IN: gfl2/patterns/daily_gunsmoke.py's score and header-
        stats-row debug-crop filename sites now build via `FieldId.score()`/
        `FieldId.header()` instead of hand-formatting the string inline --
        safe immediately since those are diagnostic PNGs under
        tests/outputs/daily/, never matched as a GT-file key. The
        stat-cell (pct/val) generators (tests/conftest.py, tests/
        generate_stat_inputs.py, daily_gunsmoke.py's stat-cell fallback
        logging) are NOT yet switched -- see action_items.txt #39.

        TESTED: tests/test_field_id.py.
